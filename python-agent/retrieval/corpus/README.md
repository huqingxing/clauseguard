# 法条语料库（阶段 1）

## 为什么保留原始快照

`wikitext/` 里是从维基文库抓下来的**原始 wikitext 快照**，`*.jsonl` 是脚本从这些快照
确定性解析出来的产物。两层都提交，是为了让语料可逐字追溯、并且在完全断网时也能重建：
如果只留 jsonl，日后再也说不清某条法条是不是被改写过，检索评测的命中率也就失去意义。

解析全程**不用 LLM、不做语义切分**：法条自带「第X条」硬标记，规则解析 100% 可复现，
也不会把法律原文改写成模型「觉得更通顺」的版本。

## 来源与许可

- 来源：[维基文库（中文）](https://zh.wikisource.org)，通过 MediaWiki API
  `action=parse&prop=wikitext&format=json&formatversion=2` 获取，抓取日期 **2026-11-06**。
- 维基文库文本按 **CC BY-SA 4.0 / GFDL** 发布，使用时需保留署名与相同方式共享；
  本仓库仅用于本地检索实验与评测。**若随产品分发，需先由法务确认合规**，并在分发物中
  附上来源与许可声明。
- 法条属于公开规范性文件，但页面排版、校勘与注释是编辑者劳动成果，不能当作无版权数据。

**为什么是 9 部而不是任务下限的 2 部**：任务要求「切分后 chunk 数 2000–3000」。真实法条
平均只有 ~96 字、最长不足千字，512/256 字定窗几乎不会产生额外切片——3 部法律时 5 种
策略都只有 1624–1670 个 chunk，达不到区间。靠伪造条文或人为缩小窗口都属于造假，因此
改为**增加真实法条条数**到 2584，使 5 种策略同时落进 2000–3000（也消除了「按哪个策略
算」的口径歧义）。新增的 6 部都选与合同/商事审查相关的领域，避免引入刑法之类无关噪声。

## 每条格式

`*.jsonl` 每行一个 JSON 对象，字段固定：

```json
{"law": "民法典", "article": "第五百八十五条", "chapter": "第三编 合同", "text": "..."}
```

`text` 里的**款**（法条内自然段）用换行符 `\n` 分隔，这是 `S4_paragraph` 能按款切的前提。
`chapter` 取该条所在的最高层标题（民法典为「编」，其余为「章」）。

## 重建与校验

```bash
cd python-agent
.venv/Scripts/python.exe -m retrieval.corpus.build_corpus   # 快照 -> jsonl + 条号连续性校验
.venv/Scripts/python.exe -m retrieval.stats                  # chunk 统计 + 随机 20 条偏移断言
.venv/Scripts/python.exe -m pytest tests/test_chunker.py -v # 5 策略单测
```

`build_corpus.py` 的硬校验：每部法律条号 `1..N` 连续、无重复、正文非空、总条数 ≥ 800；
输出 `未匹配行` 计数用来暴露 wikitext 里格式意外的行，防止正文被静默丢弃。

## 两处需要知道的解析分支

1. **民法典附则**：维基文库该页是 PDF 扫描页转置（`<pages .../>`），wikitext 里没有正文。
   第 1259、1260 条从同一页的**渲染层 HTML**（`action=parse&prop=text`）提取，规范化了
   链接产生的书名号空格；原始 API 响应保留为 `civil_code_08_supplementary.api.json` 备查，
   转换结果与其它快照同构，所以解析器不需要为它开特例分支。
2. **无 `<onlyinclude>` 的页面 / BOM 零宽字符**：企业破产法整篇即正文、反不正当竞争法部分
   款行带 `\ufeff` 前缀。解析器分别做了兼容，否则前者会解析出 0 条、后者会静默丢 14 行款。
