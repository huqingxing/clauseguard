### 切分策略是否真的改变了结果

主矩阵里同一列常出现多行数值相同，这不等于切分器没生效：命中判定按 `article`，切分只决定「同一法条的哪个片段排在前面」，不改变 article 集合；逐 query 的正负变化在 macro 平均里还会互相抵消。下面以每列第一个策略为基准，统计逐 query 指标真正发生变化的条数。

| embedding | 相对基准策略 | 逐 query 变化条数 | Δrecall (macro) |
| --- | --- | --- | --- |
| `E1` | `S2_fixed512` | 0 / 80 | +0.0000 |
| `E1` | `S3_fixed256` | 2 / 80 | +0.0000 |
| `E1` | `S4_paragraph` | 5 / 80 | +0.0000 |
| `E1` | `S5_context` | 15 / 80 | +0.0188 |
| `E2` | `S2_fixed512` | 1 / 80 | +0.0000 |
| `E2` | `S3_fixed256` | 5 / 80 | -0.0042 |
| `E2` | `S4_paragraph` | 9 / 80 | -0.0250 |
| `E2` | `S5_context` | 16 / 80 | -0.0375 |
| `E3` | `S2_fixed512` | 0 / 80 | +0.0000 |
| `E3` | `S3_fixed256` | 4 / 80 | +0.0000 |
| `E3` | `S4_paragraph` | 3 / 80 | +0.0000 |
| `E3` | `S5_context` | 13 / 80 | +0.0125 |

基准策略为 `S1_whole`。`S2_fixed512` 与基准逐 query 完全一致是真实结论而非 bug：512 字窗口大于语料里绝大多数法条，阶段 1 统计里它只比整条切分多出 9 个 chunk，而这 9 条不在 80 条查询的 gold 中；`S5_context` 因注入「法律名+章节+条号」前缀，变化最明显。若要放大策略差异，需要增加长法条 / 跨款提问，而不是改指标口径。


**最优 vs 次优**：`S2_fixed512|E2` → `S5_context|E3` 的 Δrecall=+0.0063，95% CI=[-0.0750, +0.0875]，置信区间含 0，差异不显著，不能据此断言该组合更优。
