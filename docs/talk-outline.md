# 3 分钟技术讲解提纲（架构 / 难点 / 数据）

> 面向：面试官 / 技术评审 / 内部立项。目标不是讲完功能，而是让人相信三件事：
> 你知道自己在哪层做取舍、你踩过哪些真坑、你的数字能被复现。

## 0:00–0:45 架构：为什么是双栈，而不是「一个 Spring Boot 全干」

- 一句话定位：**Java 管业务与数据主权，Python 管编排与推理**，中间是 SSE 事件 + 契约。
- 三条硬边界（说边界比说功能更有说服力）：
  1. Python 不碰 MySQL——合同/审批/审计只走 Java 的 REST/MCP，被攻破也拖不到库。
  2. 前端只连 Java——不直连推理服务、不持密钥。
  3. 跨服务字段由 `contracts/events.schema.json` 锁死（`additionalProperties=false`），
     改字段先改契约再改两端。
- 一句收：**契约先行不是为了好看，是为了让两栈能独立演进而不互相猜。**

## 0:45–2:15 三个真难点（每个都带「我最初怎么想错」）

**难点 1｜并行不是加个 gather（对应 ADR-0002）**
- 最初：节点内 `asyncio.gather` 并发调 6 个 agent——代码最短。
- 撞墙：并发藏在节点里 → 图上看不到、checkpoint 没法在分片级恢复、预算门控失去粒度。
- 定案：`Send` 动态派发 + 纯函数 reducer（findings 去重并集 / budget 求和 / degraded 取或）。
- 数字：同语料同延迟，P95 **3244ms → 967ms（−70.2%）**。

**难点 2｜引用幻觉只能靠代码堵（对应 ADR-0003）**
- 最初：prompt 里写「必须引用真实法条」。
- 撞墙：模型会编「《民法典》第九百九十九条」——格式完美，业务方看不出来。
- 定案：三道确定性闸——工具返回建白名单 → 引用按白名单条目**重建**（不采信模型自带文本）
  → critic 用「产出时检索快照」复核。被丢空就降级 `unverified` 保留 finding。
- 一句价值判断：**宁可标「不可信」，不可静默删结论**——漏判比误判更难被发现。

**难点 3｜审批要能跨进程（对应 ADR-0004）**
- 最初：把待审项写回图状态再 resume。
- 撞墙：`aupdate_state()` 会清掉 pending interrupt，`Command(resume=...)` 无处恢复，render 永不执行
  （最小复现验证过）。
- 定案：序号随 `run_registry` 落库、图状态只放业务事实；恢复只重跑 `human_approval` + `render`。
- 顺带：`cache_store` 必须排在 `human_approval` **之前**，否则审批期间的增量运行全 miss。

## 可能被追问（准备一句话回答）

1. **为什么不用 CrewAI / AutoGen？** 它们没有 LangGraph 那种「图级中断 + checkpoint 持久化」，
   而审批必须跨进程恢复；换框架等于把断点语义重写一遍。
2. **Python 侧挂了怎么办？** Java 有 Resilience4j 熔断（30s 窗口、50% 失败率），
   打开后直接 503 且可重试；事件重放存 Redis，前端带 `Last-Event-ID` 续传。
3. **演示里是真的模型吗？** 演示/压测用确定性替身，因为要可复现且不能现场烧配额；
   真实模型改一个环境变量（`MODEL_BACKEND=live`），图与校验一行不改。
4. **39% 误报是不是太高？** 这是关键词替身的代价，不是系统的天花板；它的意义是「有基线」——
   真模型跑同一套评测，涨跌可量化，而不是拍脑袋说「效果不错」。
5. **为什么条款定位准确率 100%？** 合成语料一条款=一句，span 恰好重合，区分度有限；
   真实合同多句条款才有区分度，这一项我在报告里标了限制而不是当成绩。
