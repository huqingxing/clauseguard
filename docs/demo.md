# ClauseGuard 90 秒界面演示（上传 → 审批 → 下载）

> 目标：90 秒内走完「上传 → 六专家并行点亮 → 风险清单 → 切管理端登录 → 审批 →
> 回用户端看状态 → 下载批注 Word」。**全程不手动刷新页面。**
> 终端版（curl + 事件流）见 [demo-script.md](demo-script.md)，两份脚本挑一份讲，不要混。

机器耗时实测 **35.9s / 38.8s**（两轮真实 Chrome 全程计时，见「实测计时」），
剩下的五十多秒全部是旁白时间——**机器不等人，人也不必等机器**。

```bash
cd web && npm run dev                     # 终端 C：前端 5173

```

- 只开两个浏览器标签：`http://127.0.0.1:5173/`（用户端）与
  `http://127.0.0.1:5173/admin.html`（管理端，未登录时是登录卡）。字号 18pt 以上，关通知。
- 提前跑一遍预热 JVM 与解析器，记下那次的 reviewId 兜底。
- 批注稿要能下载，得让对象存储里有源 docx（MinIO 起来即可）。本机没有 Docker/MinIO 时
  跑的是 S3 替身，需要把源 docx 按 `contracts/{id}/v{n}/source.docx` 摆进 local_dir
  ——这是既有缺口（README 已知限制 11），**不是演示步骤**，有 MinIO 的环境不需要这一步。

## 全程不手动刷新的三个地方（演示时别说破，出问题时才解释）

1. **审查过程**：右栏节点与事件流由 SSE 自己推进，断线按 1s→2s→4s 退避重连，
   重连带 `?since=<seq>` 只补缺失那一段，所以计数不会翻倍。
2. **待审批队列**：它是 30 秒轮询 + 右上角「刷新」按钮。刚停下那笔可能还没进屏，
   **点「刷新」，别刷新整个页面**（刷新页面要重新登录）。
3. **结果页状态**：审批完成后第一次打开就是「已完成」——走的是 REST + 事件回放，
   不是靠页面自己定时刷。

## 现场兜底（按故障类型说，道歉不超过 5 秒）

| 故障 | 立刻改说什么 |
| --- | --- |
| 模型超时 / 供应商抖动 | 「正好说明为什么预算与降级做进图里：超预算的专家被跳过并标 degraded，不是整轮失败。」（等它自己降级完成） |
| 上传失败 / 500 | 「文件通道在 Java 侧，我用预热的那一笔接着讲。」→ 打开兜底 reviewId |
| 事件流不动 | 「SSE 按 seq 严格递增，我让它从断点续：`?since=` 会把断线期间的事件补回来，不会重复计数。」 |
| 队列里没有这一笔 | 「队列是 30 秒轮询，点刷新——顺便说明它为什么不建队列表：待审只是状态的一个取值，单独存表就要为『谁删掉它』负责。」 |
| 批注稿按钮不出现 | 「产物依赖对象存储里的源 docx：源没就位时 render 会明确走占位分支，不会假装生成——这是已知限制第 11 条。」 |
| 完全不配合 | 切录屏（提前录 90 秒），旁白不变，收尾：「所以我把演示也做成了可复现的脚本。」 |
